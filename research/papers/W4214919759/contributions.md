# Survey of Distributed File System Design Choices (Macko & Hennessey, 2022)

This survey systematizes the design space for building a distributed file system, providing a checklist of concrete architectural decisions rather than a single design. Key contributions for our topic: (1) a taxonomy of pointer types (local, explicit direct/indirect, computed via CRUSH/consistent hashing, DHT overlays like Kademlia) and pointer granularities (subtree, bucket, file, subfile); (2) a taxonomy of path-to-inode translation schemes — single-node metadata server, replicated namespace (GlusterFS), replicated prefix tables (AFS/Coda VLDB), remote links (Farsite, FlexGroup), shared-disk (GPFS), computed placement (GlusterFS distributed volumes, Tahoe-LAFS rendezvous hashing), overlay networks (IPFS, OceanStore), and distributed-DBMS-backed namespaces (CalvinFS, HopsFS) — each evaluated for lookup latency, metadata granularity, and partition tolerance.

Most relevant to a small (~10 node), offline-tolerant, multi-master system: the replicated-namespace and replicated-prefix-table options scale fine at this size and keep lookups local; Tahoe-LAFS shows how rendezvous hashing plus erasure coding with periodic republishing tolerates partitions and churn; Farsite shows Paxos-replicated subtrees of 7–10 nodes. The consistency section (Section 6) covers replica coordination options, including weak/eventual consistency with conflict resolution and split-brain healing, and Section 4.3 notes GlobalFS's temporary remote links for moving files across namespace partitions without blocking. It is the best map for choosing which combination of namespace, placement, and consistency mechanisms fits a small peer-to-peer FS.
