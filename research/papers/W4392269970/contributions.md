# Ensuring availability and managing consistency in geo-replicated file systems (Tofu, PhD thesis, Vinh Tao Thanh, 2017)

Tofu is the most directly applicable blueprint for a multi-master, offline-capable, eventually consistent file system with principled conflict handling. It builds a formal POSIX-like model — inodes split into *stat*, *data*, and an explicitly materialized *names* component (reverse map of directory ino → link name), covering directories, files, and hard links — and defines the FS invariants over this model. On top of it, it gives an exhaustive conflict taxonomy: direct conflicts (delete-update, file data-data, names-names, directory data-data, directory names-names) and *indirect conflicts*, notably those caused by concurrent directory renames (detected via causality between the rename that changed an object's path and later updates). Every conflict type gets a defined, deterministic resolution that preserves all concurrent updates (no silent LWW data loss), e.g. merging directory contents, deterministic generated names for naming conflicts, and defined rename semantics.

Convergence is achieved with state-based CRDTs, ensuring commutativity (deterministic file-name and inode-number generation, deterministic directory merge) and associativity (delete markers/tombstones for delete-update, systematic treatment of three-way concurrency on inodes and mapping entries). For legacy POSIX apps it introduces the *session* abstraction: a long transaction taking a consistent snapshot, giving sequential semantics locally, then atomically merging at commit with automatic conflict resolution; manual intervention is limited to renaming. Implementation details (metadata/data decoupling, directory layout in a metastore, version vectors, sequencer vs. fine-grain locking for commits) plus evaluation against Dropbox/AFS make this a concrete build guide, including the rename/move conflict cases the topic prioritizes.
