# GlobalFS: A Strongly Consistent Multi-site File System

GlobalFS (de Sousa, Halalai, Schiavoni, Pedone, Rivière, Felber; SRDS 2016) is a POSIX-compliant geo-distributed file system built from two primitives: an **atomic multicast** group-communication abstraction and multiple instances of a **single-site data store** (one per site).

**What it teaches.** The design shows how to layer a full file system over a multicast primitive: all POSIX operations (metadata and data) are implemented using only four execution modes that differ in whether reads/writes are performed locally (single-site mode) or require multicast agreement across sites (multi-site mode), plus relaxed/timed variants. Read-only operations can execute against the local replica for low latency, while namespace-mutating operations use atomic multicast to impose a consistent total order across sites — a systematic recipe for classifying every file-system operation by its consistency requirement.

**Relation to the topic.** GlobalFS is a useful *counterpoint* to eventual-consistency designs: it demonstrates the strong-consistency end of the design space, where conflicts are prevented by ordering rather than resolved afterwards. Its reliance on consensus/multicast means operations require communication among sites, so it does not directly support long offline operation or partitioned multi-master updates — the very requirement of the target system. However, several components transfer well: the per-site data store architecture (each node holds a complete local store), the failure-tolerant multicast layer that tolerates site crashes while preserving consistency, and the classification of operations by coordination need. The evaluation across all EC2 regions also shows the practical cost trade-offs (local vs. strongly consistent global operations) that a small multi-master system must weigh when deciding which operations can be handled optimistically offline versus which need coordination on reconnection.
